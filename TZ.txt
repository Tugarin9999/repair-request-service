Сервис
Для кого: Ремонтная мастерская
Результат: Маршрут заявки от приёма до выдачи
Время: ~12–15 часов за неделю
Рекомендуемый стек: Python + Streamlit + SQLite.

Основная цель
Сделать ремонт прозрачным: клиент по номеру видит статус заявки, мастерская не отвечает на звонки «когда будет готово».

🧩 Задача клиента
Клиент звонит за статусом, потому что мастерская не ведёт прозрачный учёт.

Как клиент мастерской, я хочу по номеру заявки видеть статус ремонта, чтобы не звонить каждый день.
👥 Пользователи и главный сценарий
Клиент — оставляет заявку и проверяет статус.
Мастер — ведёт список заявок и меняет статусы.
Главный сценарий:

Клиент заполняет форму: устройство, неисправность, контакт.
Получает номер заявки.
Мастер меняет статус: принято → диагностика → ремонт → готово → выдано.
Клиент вводит номер и видит текущий статус и комментарий.

Состав MVP
Форма обращения, номер заявки, статусы, список мастера и страница проверки статуса.

🖥️
Экраны
• Форма заявки.
• Номер заявки.
• Проверка статуса.
• Список мастера.
🗄️
Данные
• Заявка: номер, устройство, неисправность, контакт, статус, комментарий, даты.
Критерии готовности
Статус меняется только для существующей заявки; клиент видит обновление по номеру.

 Номер заявки уникален.
 Статус меняется только у существующей заявки.
 Клиент видит обновление по номеру.
 Несуществующий номер показывает понятное сообщение.
 Клиент не видит чужие контакты.
